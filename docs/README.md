# Docs index

Specs and plans first, then design notes, then result analyses. Read
in this order on a fresh checkout.

- `SPEC.md`: build spec, framing rules, safety boundaries, model table, schedule. Marked stale in places, see report.
- `PRD.md`: original product sketch from day one. Early and partly stale, see report.
- `SCENARIOS.md`: generated scenario design, weakness catalog, difficulty table, seed sets, worked examples.
- `STAGE2_NOTES.md`: Docker stacks for generated specs, scenario selection flags, frozen playbooks, parity harness.
- `STAGE3_RUNBOOK.md`: copy-paste commands for the held-out benchmark, in order, with resume steps.
- `VOICE_API.md`: voice takeover contract: routes, order language, demo path, dashboard needs.
- `BASETEN_NOTES.md`: open-weights blue findings, quirks, and recommended flags.
- `AUDIT_EVAL.md`: auditor eval cases and scores.
- `CAMPAIGN_DIAGNOSIS.md`: how stale logs plus a red-sees-blue leak contaminated the first campaign (thrown out).
- `CAMPAIGN_RESULTS.md`: honest rerun analysis, memory versus control, with explicit non-claims.
- `arena_prototype.html`: early dashboard mockup, kept for reference.
